## 7.1. Introduction
This chapter explains our testing strategy. We verified the security, workflow state machine, and data synchronization of the portal across three testing phases.

### 7.1.1. Unit Testing
Unit testing focused on verifying individual functions in isolation. We tested password Bcrypt hashing, TOTP key generation, and bilingual Hindi-English UI labels mapping.
During unit testing, we verify validation helper utilities using mock test arrays, ensuring edge cases such as empty inputs, invalid character lengths, and format anomalies are handled before code compilation.
To perform unit tests, we isolate functions from server contexts:
- Bcrypt: Mock salt values and query database keys to assert correct hash verification. We use Mocha and Chai libraries to assert that the generated hashes are 60 characters long and correspond to the input passwords.
- TOTP: Feed predefined timestamp matrices to the time step generator, checking dynamic truncation values against outputs. We pass Unix timestamps representing 30-second intervals to verify code changes.
- Validation: Pass invalid IMO strings and check validation outputs. We verify that 6-digit or 8-digit strings, or non-numeric inputs, are rejected by the validator regex patterns.

### 7.1.2. Integrate Testing
Integration testing verified interactions between modules. We tested the sequential voyage stepper transitions, API JWT validations, and database document creation.
In this phase, we verify that state machine actions triggered by port health officers update the clearance model, lock fields dynamically, and emit event triggers captured by the customs department dashboards.
Integration tests check endpoint routes:
- User Registries: Assert HTTP 201 on new users and HTTP 403 on login before admin approval.
- Vessel CRUD: Verify that duplicate IMO numbers trigger HTTP 400 errors.
- Stepper Routes: Simulate sequential PUT requests to ensure stepper statuses update in order.
We use Supertest to mock HTTP requests and verify that Mongoose validations and database operations complete without schema warnings.

### 7.1.3. System Testing
System testing verified the end-to-end user workflows: account registration, admin approval, 2FA setup, vessel registry, clearance stepper decisions, PDF document compiling, and QR code verification.
This testing ensures that network failure recovery workflows execute correctly, caching requests locally inside browser storage and synchronizing updates upon connection restoration.
System testing covers:
- Session Timeout: Verify that idle states trigger auto-logout and redirect workflows.
- Offline Fallbacks: Simulate server drops, verify localStorage updates, restore connections, and check database synchronization.
- jsPDF: Confirm that clicking download compiles bilingual certificates with verification QR codes.
We use Selenium Webdriver to automate browser sessions, verifying page elements, forms inputs, and styling variables across different viewport widths and zoom scales.
