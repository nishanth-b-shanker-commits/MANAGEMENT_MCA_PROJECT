## 6.1. Login Screen
The Login interface features a top accessibility bar (Hindi/English toggle, font scaling controls A-/A/A+, and theme selector), a tricolor header accent, and role-based login selection tabs. Shipping agents and port department officials select their roles before inputting their credentials. A reCAPTCHA check is built in to block automated scripts. If two-factor authentication is active on the account, the login card transitions to show the TOTP input field.
To manage accessibility, the screen layouts enforce a strict focus layout order, ensuring keyboard users can access inputs sequentially. Visual error highlights provide clear feedback if users enter invalid data. Below is the screenshot of the Login interface:

## 6.2. Main Screen/Home Page
After logging in, users access their customized dashboards. The top navigation bar displays the state emblem and NMPA details. The home dashboard features quick summary counters (Registered Vessels, Active Voyages, and Clearance status alerts). Interactive charts display daily approval metrics. Real-time NMPA weather details are also displayed, showing wave height, wind speeds, and pilot safety indicators. Below is the screenshot of the Agent's Main Dashboard:

## 6.3. Collapsible Sidebar Menu
The collapsible sidebar menu dynamically renders options based on the user's role:
- Ship Agent: Renders links for the main Dashboard, Vessel Registry, and Clearance Workflow list.
- Port Officers: Displays pending review queues for their respective departments.
- System Administrator: Displays options for User approvals, Settings, and Audit logs.

## 6.4. Vessel Registry Form
Shipping agents use the Vessel Registry form to enroll ships. The form includes inputs for the vessel's name, IMO number, flag state, classifications, gross tonnage (GRT), and net tonnage (NRT). Submitted records are stored in the database and linked to the agent's account.
The registration layout features field helpers and error prompts. If an agent enters an invalid or duplicate IMO number, the input field highlights in red and displays a warning message. Below is the screenshot of the Vessel Registry interface:

[IMAGE:screenshots/vessel_registry.png]

## 6.5. Validation Rules
The interface runs real-time form validation:
- IMO numbers must be exactly 7 digits.
- Tonnages must be positive numbers.
- Arrival and departure dates must be logically ordered.
- All duplicate registrations are rejected with an error warning.

## 6.6. Clearance Workflow Table
The Clearance Workflow page displays voyage applications in a table. Shipping agents can track their sequential review progress through PHO, Customs, and Traffic columns. Clearances are color-coded (green for approved, yellow for pending, red for rejected). Once fully approved, the row displays download buttons for the bilingual clearances. ## 6.12. Custom Styling CSS Specifications
The single window portal UI layout is styled using standard vanilla CSS with customized variables to render responsive grids and tricolor theme tokens.
The layout uses a saffron and green tricolor theme with light and dark mode mappings. Accessibility styles are defined using CSS variables that adjust font sizes dynamically. Input components utilize modern transitions, border outlines, and box shadows.

To maintain a consistent government visual identity, NexaPort defines theme tokens mapping specific color values to official Indian tricolor representations:
- `--primary`: Saffron (#FF9933) represents strength, courage, and federal administrative authority.
- `--secondary`: Green (#138808) represents growth, port safety, and operational clearance.
- `--bg-main`: White (#FFFFFF) represents clarity, truth, and seamless single-window transparency.
- `--text-main`: Dark slate gray (#000000) or cream white (#F1F5F9) ensures high contrast.
These variables dynamically update root styles when the user toggles dark mode or scales accessibility typography, maintaining WCAG contrast ratios across components.

## 6.13. UI Localisation and Language Dictionary Mappings
The user interface supports Hindi and English, loading dynamic key dictionaries locally. Text strings for table headers, form inputs, navigation buttons, and status labels are stored in a translation dictionary.
When the user clicks the Hindi/English toggle button on the top bar, the system updates the state variables, triggering a refresh of all on-screen content. This localized model ensures compliance with national language guidelines and makes the Single Window Portal accessible to agents and port officials from diverse backgrounds.
