1.1. Introduction of the System
We developed the Port Digital Clearance System, dubbed NexaPort, to sort out a massive practical headache at the New Mangalore Port Authority (NMPA) situated in Panambur, Mangaluru. Right now, getting a commercial ship cleared to enter or leave the port involves a mountain of paperwork. A cargo vessel cannot just walk in, drop off containers, and sail away. It has to get the green light from three different departments: Port Health, CBIC Customs, and Traffic Control. In the traditional manual system, shipping agents literally run from office to office across the port with folders of paper documents, waiting in lines just to get ink stamps and signatures. NexaPort changes this entire process by replacing paper files with a secure, centralized web portal.

Shipping agents log into the portal, register their merchant vessels, upload light house dues receipts, and track their voyage applications from their desks. On the other side, port officials from the three departments use role-restricted dashboards to review applications, record logs, and approve or reject submissions in a strict sequence: first Port Health, then Customs, and finally Traffic Control. When all three departments give their approval, NexaPort compiles a bilingual PDF clearance certificate containing a verification QR code for pilot boarding checks. We built the backend using Node.js and Express, set up the frontend with React, and stored all records on a MongoDB Atlas cloud cluster. We also added an offline sync adapter using browser LocalStorage so agents do not lose their draft forms if the port's network cuts out.

1.1.1. Project Title
The project is officially titled "Port Digital Clearance System for NMPA Mangaluru" (internally referred to as NexaPort). We built this application specifically to handle the actual administrative workflows, local security guidelines, and tricolor style standards required by the port authority at Mangaluru. Even so, we designed the database and API routes to be modular, meaning the entire system could easily be configured for other major Indian ports in the future.

1.1.2. Category
This project belongs to Enterprise Web Applications and Workflow Automation. It is a full-stack system using a single-page React frontend, an Express API middleware layer, and a NoSQL database tier. The core features include secure user onboarding, Time-based One-Time Passwords (TOTP) for two-factor authentication, database auditing, and browser-side PDF document generation.

1.1.3. Overview
NexaPort is a single window portal connecting shipping agents and port officers. Shipping agents register their merchant vessels, upload receipts for Indian Light House (ILH) dues, and monitor their clearance status. Port officers log in using role-restricted accounts to review applications. The approval flow follows a sequential stepper: the Port Health Officer checks crew health lists, the Customs Officer verifies cargo manifests, and the Traffic Controller checks berthing slots. Once everyone approves, the portal generates a bilingual (Hindi and English) clearance certificate. We added security features like Bcrypt password hashing, JWT session verification, and Google Authenticator TOTP. The interface is built with accessibility in mind, featuring font scaling controls (A-, A, A+) and a low-glare dark mode. We also built an offline mock fallback database using browser LocalStorage to keep the system running during connectivity issues.

1.1.4. Comparative Analysis with International Port Portals
To design NexaPort's logic, we studied how some of the busiest ports globally handle clearances. For example, Singapore uses Portnet to tie together shipping lines, terminal operators, and government agents. In Europe, the Antwerp Port Community System (APCS) coordinates customs and logistics data, while Rotterdam relies on Portbase to manage traffic flows across the Netherlands.
These platforms are highly complex national systems, but they share the exact same core concept as NexaPort: a single-window portal that coordinates sequential clearances. NexaPort applies these workflow automation principles at a local port level, tailored to NMPA Mangaluru, proving that local ports can achieve massive efficiency gains without needing massive national infrastructure.

1.2. Background
Before NexaPort, getting clearance at NMPA was a slow, paper-heavy process. Shipping agents had to spend hours walking files between distant port offices:
- Port Health Organisation (PHO): Located outside the main harbor, where agents filed crew health lists and sanitation certificates. This step is critical to prevent infectious diseases from entering the country, following the WHO International Health Regulations (IHR 2005).
- Customs Department: Located at the main administrative office, where agents filed cargo manifests and paid Indian Light House (ILH) dues. Customs officers checked cargo records and payment receipts.
- Traffic Manager: Located at the harbor terminal, where agents verified berth assignments and pilot requests. The Traffic Controller coordinated with harbor pilots to guide the vessel in.
This manual process caused significant ship waiting times at anchorage, high demurrage fees, and coordination bottlenecks. Digitizing this sequence into an online Single Window environment addresses these issues directly.

1.2.1. Introduction of the Company
The New Mangalore Port Authority (NMPA) in Panambur, Mangaluru, is one of India's major deep-water ports on the west coast. Under the Ministry of Ports, Shipping and Waterways, NMPA handles over 50 million metric tonnes of cargo annually, including crude petroleum, coal, LPG, LNG, and containers. The port has 14 active berths, processing hundreds of vessel arrivals monthly. Automating clearances at NMPA supports paperless port operations and aligns with the Government of India's Ease of Doing Business initiatives. By replacing manual paperwork with NexaPort, NMPA aims to set a benchmark for digital maritime single-window portals in India.

1.2.2. NMPA Infrastructure and Traffic Overview
New Mangalore Port features advanced maritime infrastructure, handling bulk cargo, liquid chemicals, crude oil, and container carriers. The port handles major industrial materials like coal, iron ore, limestone, liquid LPG, LNG, and fertilizers. Managing these operations requires high administrative speed. Under the manual paper-based clearance system, coordination between vessels, shipping lines, and government entities was slow. Vessel delays at anchorage led to demurrage penalties. NexaPort addresses these coordination challenges by providing a secure online stepper that links shipping agents with PHO health officers, CBIC customs checkers, and NMPA traffic managers.

1.2.3. Project Software Development Life Cycle (SDLC) Methodology
We chose an Agile SDLC model to build NexaPort. The complex requirements of multi-department workflows and security standards meant we needed an iterative approach. We organized development into five two-week sprints:
- Sprint 1: Identity and Security. We configured the Express server, built the MongoDB collections, set up Bcrypt hashing, and implemented admin-approved registration logic.
- Sprint 2: Core Workflow. We built the Vessel Registry forms, added 7-digit IMO validations, and implemented the sequential stepper for health, customs, and traffic clearances.
- Sprint 3: Document Compilation and Accessibility. We integrated client-side jsPDF certificate generation, pilot verification QR routes, font scaling controls, and the tricolor style variables.
- Sprint 4: Offline Synchronization and AI Bot. We built the client-side localStorage Axios interceptors, the Sagar Setu chatbot console, and the SMS alerts system.
- Sprint 5: Testing and Deployment. We ran 80 validation scenarios, configured MongoDB replica sets, and fixed layout spacing issues.
Agile sprints allowed us to incorporate feedback quickly and refine the system, ensuring all security, accessibility, and functional requirements were met.
